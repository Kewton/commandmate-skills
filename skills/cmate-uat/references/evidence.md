# 証跡（evidence）の必須項目と redaction

SKILL.md 第 4 節 Step 4 の正本。

証跡の役目は 1 つである。**判定の根拠が、実行者の記憶ではなくファイルとして残ること。**
離席から戻った人と、後でこの run を疑う第三者が、同じものを読んで同じ結論に至れることが要件である。

---

## 1. 置き場所

```
<run_dir>/evidence/
  EV-01-tc-2590-01-command.txt
  EV-02-tc-2590-03-screenshot.png
  EV-03-isolation.txt
```

- 1 証跡 = 1 ファイル。`EV-<連番>-<TC id>-<種別>` で名前を付ける。
- `acceptance/issue-<n>.json` の `evidence[].id` と `path` がこのファイルを指す。
- **`run_dir` の外に書かない。**

---

## 2. 種別ごとの必須項目

### 2.1 `command`

| 項目 | 必須 | 内容 |
|---|---|---|
| 実行した command | 必須 | **実際に打った文字列**。整形しない |
| exit code | 必須 | 実測値。`0` を期待していても実測を書く |
| stdout / stderr | 必須 | 長い場合は末尾を残して切り、切ったことを明記する |
| 実行時刻 | 必須 | 開始時刻 |
| cwd | 必須 | どこで実行したか |

**「成功しました」と書かない。** exit code と出力が証跡であり、要約は判定側の仕事である。

### 2.2 `http`

command に加えて、URL・method・status code・応答本文（必要な範囲）を残す。
**認証ヘッダと Cookie は値を残さない**（第 4 節）。

### 2.3 `screenshot`

| 項目 | 必須 | 内容 |
|---|---|---|
| 画像 | 必須 | PNG |
| 何を見せている画像か | 必須 | 1 行。「Logs タブの警告つき行」など |
| 撮った時点の URL / 画面 | 必須 | どこを撮ったか |

**画面に個人情報・私有リポジトリ名・絶対 path が写り込む。** 撮る前に見て、写るなら
撮り方を変えるか、該当部分を伏せてから保存する。

### 2.4 `isolation`

第 4 節 Step 3 の `isolation.checks` の**実測結果**である。1 件ごとに command と exit code を
残し、**報告書の「環境」節からも参照できるようにする**。

隔離の証跡は他と役割が違う。他は「機能が動いた」の根拠だが、これは
**「この run が本番を壊していない」の根拠**である。省略しない。

### 2.5 `manual`

人が目で見て確かめた項目。何を見て何を確認したかを 1 段落で書き、**誰が見たかは書かない**
（個人を特定する情報を証跡に入れない）。

**この Skill が `manual` を自分で作ることはない。** 画面を触れない TC は `manual_pending`
であって `manual` ではない —— 前者は「まだ誰も見ていない」、後者は「人が見た」である。
この差を潰すと、申し送りが消える。

## 3. flaky の記録

同じ TC を再実行して結果が変わったら、**両方の実行を別々の証跡として残す**。
後の実行で上書きしない。

```
EV-05-tc-2590-02-command.txt      # 1 回目: exit 1
EV-06-tc-2590-02-command-retry.txt # 2 回目: exit 0
```

outcome は `flaky` であって `pass` ではない。**「2 回目は通ったので pass」としない。**
何回実行して何回落ちたかを証跡から数えられる状態にする。

---

## 4. redaction

証跡に残してはならないもの。

| 種類 | 扱い |
|---|---|
| token / API キー / パスワード | **値を残さない。** `<redacted>` に置換し、置換したことを書く |
| 認証ヘッダ・Cookie | 同上 |
| 環境変数の値 | **設定されているか否かだけ**を書く（`CM_DB_PATH: set` / `unset`） |
| 個人名・メールアドレス | 伏せる |
| 私有リポジトリ名・組織名 | 対象そのものでなければ伏せる |
| `$HOME` 配下の絶対 path | 必要なら `~` に畳む |

**置換したことを必ず書く。** 黙って消すと、証跡を読む人が「元から無かった」と読む。

`env.up` の command 文字列そのものが証跡に入るので、**そこに秘密を直書きしない**
（`uat.yaml` は commit されるので、そもそも秘密を書く場所ではない）。

---

## 5. 切り詰め

出力が長い場合は末尾を残して切る。**切ったことと元の行数を書く。**

```
--- stdout (last 50 of 1,284 lines) ---
...
```

失敗の原因は末尾に出ることが多いので、先頭ではなく末尾を残す。
**「長いので省略」だけ書いて中身を捨てない。**
